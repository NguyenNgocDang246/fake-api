# src/app — Agent Guide

## Summary

Everything Next.js routes: the API route handlers under `api/**`, and the UI. The UI is a thin presentation layer over React Query and react-hook-form; anything that decides something lives in `src/server/` or `src/models/`, so a rule is never enforced only in a component.

## Content

- `api/**` — route handlers. Composed from the `src/server/core/route_helpers.ts` chain (`createRouteHandler` or `createStaticRouteHandler`, then `withUserId`/`withProjectId`/`withEndpointGroupId`/`withEndpointId`), with the permission check inside the innermost handler. `api/fake/[projectId]/` is the public one that serves a user's mock endpoints.
- `(pages)/**` — the routed UI, grouped per page. A page owns a `page.tsx`, a `viewmodel.ts` and a `components/` folder. `(pages)/(marketing)/**` holds the search-facing landing pages, which are prose plus the `components/Marketing/**` kit and have no viewmodel. Two of them, `mock-api-generator/` and `fake-json-api/`, lead with the product; three, `free-api-for-testing/`, `dummy-json-data/` and `json-to-api/`, are guides that have to be worth reading without it, and `faq/` answers both. Their URLs are flat, with no `/blog` prefix, and each one owns a keyword cluster nothing else on the site targets, so a heading is never reused across two of them. Product-led and guide describe how the copy opens, not a grouping to show a reader: all five land on the same product with the same call to action, so the footer lists them flat, in one row with no headings.
- `(home)/**` — the landing page, plus `components/GuestPlayground/`, the client island where a visitor with no account builds and calls up to `ROLE_LIMITS.GUEST.maxEndpointsPerGroup` endpoints. It reuses the project page's endpoint components as they are and remembers which sandbox belongs to this browser in `localStorage` under `GUEST_SANDBOX_STORAGE_KEY`, because a visitor has no session to hang it on. The page renders it only when nobody is signed in.
- `components/**` — the shared UI kit: inputs (`DefaultInput`, `ComboInput` for a searchable dropdown that optionally creates values, `Checkbox`, `Switch`, `JsonEditor`), `Input/RepeatableRowList` for an add/remove row list (the response-header and CORS-origin editors), `Tabs/PillTabs` for a tab strip, either as pills sized to their labels (the preview switcher) or, in its `card` variant, as tabs sharing the full width evenly; `Tabs/FormTabs` for a whole tabbed form section, always on the `card` strip: it takes one entry per tab (`label`, `hasError`, `marked`, an optional `title`/`description`, and the `content` the caller builds) and owns the strip, the dots, keeping every panel mounted, and moving to the first broken tab on a failed submit, `Code/CodeBlock` for a fenced snippet, `Decor/HeroGlow` for the blurred background wash behind a hero, `Text/EmptyState` for the "nothing here yet" block (title, optional description, and a button the caller supplies, so it stays free of any one page's action), `Notify`, `JsonLd` for a structured-data script, `Marketing/**` (`MarketingHero`, `FeatureGrid`, `StepsRow`, `CtaBanner`, and `ComparisonTable` for a table that scrolls inside its own `overflow-x-auto` box rather than widening the page) for the blocks the home and landing pages share, the modal wrapper with its `ModalSize` scale, the React Query wrapper and its `QUERY_KEY`/`STALETIME` constants.
- `styles/globals.css` — the only stylesheet: the Tailwind v4 entry, the `--scroll-*` and toast tokens, the global scrollbar treatment, and the `react-toastify` skin.
- `libs/helpers/**` — pure helpers shared by both halves of the app. See [libs/helpers/AGENTS.md](libs/helpers/AGENTS.md).
- `libs/routes.ts` — `API_ROUTES` and `PAGE_ROUTES`, the one place a URL template is written.
- `libs/seo.ts` — `SITE` (name, absolute URL, description), `absoluteUrl`, `buildMetadata`, which every page calls instead of writing a `Metadata` object by hand, and `breadcrumbSchema`, which turns the page's `Crumb[]` into its `BreadcrumbList`.
- `robots.ts`, `sitemap.ts`, `manifest.ts`, `opengraph-image.tsx`, `twitter-image.tsx`, `icon.png`, `apple-icon.png` — Next file conventions for the crawler-facing and share-facing assets.

## Conventions

- **A component folder is `ComponentName/ComponentName.tsx` plus a `viewmodel.ts`.** The `.tsx` renders; the viewmodel is a hook holding the React Query state, the mutations and the modal opening. A `*Skeleton.tsx` sits beside them when the list has a loading state. Files here are `PascalCase` for components and lowercase for the rest, which is the one place the repo's `snake_case` file rule does not apply.
- **An endpoint component takes its project id and its route templates as props.** `CreateEndpointForm`, `UpdateEndpointForm` and `EndpointItem` all default to the project page's behaviour (project id read off the pathname, `API_ROUTES.ENDPOINT`), and the home page's trial box passes `projectId`, `endpointRoutes: API_ROUTES.GUEST.ENDPOINT` and `aiAvailable: false` instead. It has to be props and not context: a modal's children are created in the caller's scope but rendered under `ModalWrapper` near the root, and context resolves where a node renders. `EndpointForm` unmounts the AI panel rather than hiding it when `aiAvailable` is false, because that section fetches its own status and quota.
- **A form is driven by its modal, through a ref.** The form is a `forwardRef` exposing `useImperativeHandle(ref, () => ({ submit }))` where `submit` resolves `true` or `false`, and the viewmodel holds the `formRef` and passes `onSubmit` to `modal.openModal({ type: "form", ... })`. The modal decides whether to close; the form never does.
- **A `customResolver` checks by hand first, then delegates to `zodResolver`.** Coercions and the checks Zod cannot phrase run first and short-circuit; everything else is the shared schema's job. The schema in `src/models/**` is the single source of every limit and every message, so a form must never restate a rule it could import. Where the browser can prevent a value outright (`maxLength` on an input), do that too, but the resolver still decides.
- **A rule the server enforces is mirrored, never re-implemented.** `validateAiFields` wraps the same `checkAiFieldSelection` the Zod schema calls, so the message a user sees before the request and the one that would come back are the same string. Two copies of a rule drift, and the drift shows up as the form and the API disagreeing about the same input.
- **A create form and its update twin share one body.** `EndpointForm` is that body for endpoints and `ProjectForm` for projects: the wrapper owns the mutation and the `useForm`, and passes `register`/`control`/`errors`/`setValue`/`submitCount` down. Both halves validate by the same schema, since `ClientUpdateProjectSchema` *is* `ClientCreateProjectSchema` (as `ClientUpdateEndpointByIdSchema` is `ClientCreateEndpointSchema`), so an update can never accept something a create refuses.
- **A repeated row keeps the index the form rendered it at.** `ResponseHeadersEditor` and the origin list in `ProjectForm` both let a user add a row and leave it empty, and both are validated by a Zod `superRefine` that skips a blank row and reports every other issue at the index it was handed, with the blank rows dropped by a transform that runs afterwards. Filtering before validating would shift an error onto the wrong row, which is the one thing a per-row message must not do.
- **A tabbed form keeps every panel mounted** and hides the inactive one, and a failed submit opens the panel carrying the first error. `JsonEditor` measures its own height once on mount and holds its undo stack in a ref, so remounting a panel throws away a half-typed body, and an error message under a hidden control is one nobody reads. `Tabs/FormTabs` is where both of those live, so `EndpointForm` and `ProjectForm` describe their tabs and nothing else. What goes *inside* a tab is not shared: the AI variants card and the project's CORS card look alike but each stays its own markup, because a panel is where a feature's design belongs.
- **A block that changes shape inside a modal measures its own container, not the viewport.** The AI section and the settings grid use `@container` with px breakpoints, because a `sm:` breakpoint says nothing about how much room a `w-[44rem]` panel actually left them. Write those breakpoints in px: `html` is 18px here, so `rem` inside a container query resolves to more than it reads as.
- **An empty list that a user can fill offers the way to fill it.** Those places use `EmptyState` with a title, a line saying what the thing is for, and the create button, rather than a bare "No X found". A list that is empty because of a filter is not this: it stays a plain `NoContentText`, since there is nothing to create. Neither is a list whose create button is already right beside it, such as the endpoint-group sidebar.
- **The UI never reports what it cannot know.** While the JSON body will not parse, the field selector says nothing about which fields exist rather than listing all of them as missing. The server side of this feature answers the same way, reporting `undefined` rather than a stale verdict.
- **Server state goes through TanStack Query**, keyed by `QUERY_KEY` and aged by `STALETIME`, and a mutation invalidates the key it touched. Answers fixed at boot are seeded with `queryClient.setQueryData` from the server component instead of being fetched. `QUERY_KEY.USER.USAGE` is the one query that opts out of `STALETIME` and runs at `staleTime: 0`: saving an endpoint can spend an AI design in an `after()` task that finishes past the response, so no invalidation can be timed against it and opening the AI card is the moment to ask again. Where a response already knows the new count, as the AI preview route's does on both its answer and its refusal, the viewmodel writes it in with `setQueryData` rather than paying for a refetch.
- **Scrollbars come from one global rule in `globals.css`.** Every scrolling element is thin and trackless, with the thumb fading in only while that element is hovered or focused within, driven by the `--scroll-*` tokens. A dark-backgrounded scroll box carries `fa-scroll--dark` (or `fa-code` / `fa-json` for a code or JSON `pre`) so its thumb stays visible; `fa-scroll` and its `--always` / `--fade` / `--fade-bottom` modifiers are the opt-in helpers. A component never restyles its own scrollbar.
- **User-facing strings are English.** Comments too.
- **A page declares its metadata through `buildMetadata`.** It fills in the canonical URL, the Open Graph block and the Twitter card from one title, description and `PAGE_ROUTES` path, so no page hand-writes a canonical or restates the site name. It names the share image explicitly, because a page that declares its own `openGraph` block stops inheriting the root `opengraph-image` file convention.
- **Thin pages are excluded with a noindex tag, never with a robots.txt disallow.** A blocked crawler never reads the tag, so the URL can still surface as a bare link. `(pages)/auth/layout.tsx` carries the one `robots: { index: false }` that covers every auth page.
- **Structured data is rendered from the same array the page renders.** The FAQ page maps one `FAQ` constant into both the visible list and the `FAQPage` schema, because Google treats a schema answer that is not on the page as a violation. The same holds for the trail: a page declares one `BREADCRUMB` array, passes it to `Breadcrumb` for the visible nav and to `breadcrumbSchema` for the `BreadcrumbList`. Figures quoted in that copy come from the shared constants (`ROLE_LIMITS`, the `endpoint/primitives.model` limits), never retyped.
- **A landing page splits its description in two.** `META_DESCRIPTION` feeds `buildMetadata` and the page's schema and measures 150 to 160 characters; `HERO_DESCRIPTION` is the longer line under the `<h1>`. One string cannot serve both, because the search snippet gets cut and the hero reads clipped. Both bounds bite: under 150 an auditor reports the description as too thin to earn the snippet, and past 160 Google truncates it. `SITE.description` sits in the same band, since it is what `/` serves.
- **`/` takes its title from the root layout's `title.default`, not from its own `metadata`.** The default is the bare site name, and the template `%s | Fake API` would turn a page-level title into "Fake API | Fake API". That layout is also the one place `openGraph` is declared without `buildMetadata`, so it names the `images` array by hand for the same reason `buildMetadata` does.
- **An outbound link goes through `TextLink` with `external`.** It swaps `next/link` for an `<a>` carrying `target="_blank"` and `rel="noopener noreferrer"`, which is the pairing `NavigationButton` already applies. A raw `<a>` in a page misses the `rel` and hands the opened tab a `window.opener` reference.
- **`HeroGlow` is rendered once, by the root layout, and never by a page.** It is anchored to `body`, which carries `relative` for it, so every page sits on the same wash and no page has to remember to add one. The glow is sized to spill past its ancestor, which is how it reaches the viewport edges and fills the gap under the sticky header. It contains its own horizontal bleed with `overflow-x-clip` on its container: that container is `inset-x-0`, so the cut lands exactly on the viewport edges where nobody can see it. Do not rely on the `overflow-x-clip` that `body` also carries. `body`'s overflow is propagated to the viewport and `body` itself falls back to `visible`, so it clips nothing, and a child wide enough to overflow will make the whole document scroll sideways. `clip` is still the right value on both, since unlike `hidden` it does not create a scroll container and so leaves the sticky header working.
- **The `<h1>` carries the page's target phrase verbatim.** `/mock-api-generator` says "mock API generator" and `/fake-json-api` says "fake JSON API" inside the heading itself, not only in the badge above it.
- **The pill badge belongs to `MarketingHero`, and to nothing else.** It is the tag a landing page wears above its `<h1>`, and it reads as one because no other section on the site carries it. A section that wants more weight gets it from the blocks the theme already has, the `indigo-600` to `blue-500` gradient among them, not from a second badge.

Backend conventions are in [src/server/AGENTS.md](../server/AGENTS.md); naming and ID rules that cross directories are in the root [AGENTS.md](../../AGENTS.md).
