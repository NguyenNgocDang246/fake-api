# src/server/core — Agent Guide

## Summary

Cross-cutting utilities shared by every service. Not domain-specific.

## Content

- `api_response.ts` — `ApiResponse` class, static `success({ data, statusCode })` / `error({ errors, message, statusCode })`. `error` special-cases `STATUS_CODE.NO_CONTENT` to return a body-less `NextResponse`. Both build the `ApiResponseModel` envelope from `src/models/api_response.model`.
- `cors.ts` — what the fake API answers a browser with. `DEFAULT_MOCK_HEADERS` is the pair every mock response starts from (`application/json; charset=utf-8` and `cache-control: no-store`, the second because a body is edited constantly and an AI endpoint answers differently every call), and an endpoint's own headers are layered over it. `LOCKED_MOCK_HEADERS` go on after those and cannot be overridden (`content-security-policy: sandbox`, `x-content-type-options: nosniff`, `x-robots-tag: noindex`), because a mock host shares its parent domain with the app and a body a browser opens as a page must not run script there, and because that host serves no `robots.txt` of its own: `/robots.txt` on it is a mock path like any other, so the header is the only place indexing can be refused. All three are in the model's blocklist too, so an author is told rather than having a header they set quietly replaced. `buildCorsHeaders({config, origin, preflight, requestedHeaders, exposeHeaders})` returns the headers to merge, or `null` when this caller gets none, which is what makes the browser block it: CORS turned off and an origin not on the project's list both answer `null`. `applyCorsHeaders(res, headers)` merges them onto a response, appending `vary` rather than replacing it. `ALLOWED_METHODS` is a fixed list rather than one derived from the endpoints a project holds, so a preflight for a path nobody has created yet still passes and the real request answers with a readable 404.
- `errors.ts` — `AppError` (extends `Error`, carries `statusCode` + `message` + an internal `cause`, defaults to `SERVER_ERROR`/500), `ErrorValidation` (`{ message, field }`, built via `ErrorValidation.fromZodError(zodError)` which maps each Zod issue to one instance), and `guardService(run)`, the helper every service wraps its persistence call in so a driver error reaches a route as an `AppError`.
- `validation.ts` — `validateData(data, schema)`. Overloaded: pass a bare `ZodSchema` or a single-element tuple `[schema]` to force array validation. Returns `{ success: true, data }` or `{ success: false, response }` where `response` is a ready-made `ApiResponse.error` with `VALIDATION_FAILED` + 400.
- `constants.ts` — only what every domain shares: `ERROR_MESSAGES`, `SUCCESS_MESSAGES`, `RESPONSE_STATUS`, `STATUS_CODE`, and `LIMIT_MESSAGES` (the counterpart of `role_limits.ts`, since the limits it guards span projects, groups, endpoints and AI generations). Anything owned by one domain lives in that domain's own `*.constants.ts`: [../services/auth/auth.constants.ts](../services/auth/auth.constants.ts) (token expirations, `AUTH_MESSAGES`, `GOOGLE_AUTH_MESSAGES`, `TOKEN_MESSAGE`), [../services/ai/ai.constants.ts](../services/ai/ai.constants.ts) and [../services/endpoint/endpoint.constants.ts](../services/endpoint/endpoint.constants.ts).
- `ownership.ts` — `ProjectOwner`, `EndpointGroupOwner` and `EndpointOwner`, the chains that say a row belongs to a user. They are carried into a read rather than asked as a question of their own, which is what lets a GET answer in one query. See the conventions in [../AGENTS.md](../AGENTS.md).
- `prisma_retry.ts` — `createWithUniquePublicId(createFn, generate?)`: calls `createFn(generate())` up to 5 times, retrying only on a Prisma `P2002` unique-constraint violation targeting `public_id`; any other error rethrows immediately. `generate` defaults to `generatePublicId`; the project service passes `generateProjectPublicId` instead, because a project id has to survive being a hostname label.
- `rate_limit.ts` — `createRateLimiter({callsEnv, windowEnv, fallbackCalls, fallbackWindowSeconds, message})`, returning `{consume(key), reset()}`. The counted-per-key counterpart of [../services/ai/ai_rate_limit.ts](../services/ai/ai_rate_limit.ts), which counts one global stream: same env-read-once-then-cache shape, same "`calls` or `window` at `0` turns it off", same 429 `AppError`. The message is a parameter rather than a constant here, so `core/` stays free of any one domain's strings. Hits live in this instance's memory, so several deployed instances each count on their own.
- `role_limits.ts` — `ROLE_LIMITS`: a `Record<UserRole, {maxProjects, maxGroupsPerProject, maxEndpointsPerGroup, maxAiPlansPerDay}>` (`GUEST`/`USER`/`USER_VIP`), consulted before creating projects/groups/endpoints and before designing a blueprint. `maxAiPlansPerDay` at `0` means the role has no AI at all, which is a different refusal from having spent the day's allowance, so `isAiAllowed` and `trySpend` answer different questions and callers ask both. `maxProjects` means something different for `GUEST`: every visitor trying the product shares that one account, so it caps how many trial sandboxes exist at once rather than what one person may keep. It is still enforced, by `guest.service.ts` after it has swept expired sandboxes.
- `route_helpers.ts` — composable pieces for `route.ts` handlers: `withErrorHandling(handler)` wraps a handler in the standard try/catch (`AppError` → its own message/statusCode, else generic `ApiResponse.error()`). `createRouteHandler<T>(chain)` adapts a `ChainHandler` into a Next.js route export, awaiting `props.params` once; `createStaticRouteHandler(chain)` is the variant for a route with no dynamic params, such as `api/project` or `api/user`. `withUserId`/`withProjectId`/`withEndpointGroupId`/`withEndpointId` each validate one route param (via `validateData`) and add it to a shared `ctx: Record<string, string>`, short-circuiting with the validation's error response on failure — nest only the ones a given route actually needs (e.g. a project-only route just needs `withUserId(withProjectId(handler))`). Permission checks are intentionally NOT part of the chain: services' `checkPermission(s)` already re-verify the whole ancestor chain in one Prisma query, so call it once inside the innermost handler instead of once per chain level. A GET does not call it at all: it reads through a `getOwned…` carrying the chain in its `where`, and `missingOrForbidden(exists)` turns an empty answer into the 403 or the 404 it deserves, from one `…Exists` probe that only a refusal ever runs.

## Conventions

- New user-facing strings and HTTP status codes are always enum members, never inlined at the call site. HTTP status codes and messages every domain uses go in `constants.ts`; a message only one domain raises goes in that domain's `*.constants.ts` instead, so `core/` stays free of domain detail.
- `validateData` is the only sanctioned way services parse untrusted input; it already returns a pre-built `ApiResponse.error`, so callers just return `result.response` on failure.

Naming, ID, and other conventions that also apply outside this directory are in [src/server/AGENTS.md](../AGENTS.md) and the root [AGENTS.md](../../../AGENTS.md).
