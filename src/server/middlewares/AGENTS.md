# src/server/middlewares — Agent Guide

## Summary

Request-level middleware functions invoked from the Next.js middleware entry point (`src/middleware.ts`). Not domain services.

## Content

- `auth.middleware.ts` — `authMiddleware({ req, ctx, isApiRoute })`. Tries the `access_token` cookie first via `token.service.ts#verifyAccessToken`; on failure/absence falls back to `refresh_token`, re-validates the user's `token_version` still matches, mints a new access token, and stashes it on `ctx.refreshedAccessToken` (the cookie itself is set by the caller, not here) plus `ctx.userId`. Returns `null` to continue, or an `ApiResponse.error` (401) only when `isApiRoute` and both tokens failed.
- `guest.middleware.ts` — `guestMiddleware(req)`. Recognizes the `GUEST_PROXY_PREFIX` (`/api/guest/project/`) and rewrites onto the real `/api/project/**` handlers with `x-userId` set to the shared guest account, so a visitor with no session reaches the same endpoint CRUD code every signed-in user does. It accepts exactly three path shapes, `{projectId}/endpoint-group/{groupId}/endpoint`, that plus `/{endpointId}`, and that plus `/scenario/{scenarioId}/activate`, with every id checked against `PUBLIC_ID_REGEX`; everything else under the prefix is a 404. The third is the one thing reachable past an endpoint id, because a trial endpoint holds more than one saved response and switching which one answers is what they are for. That whitelist is the whole security boundary of the branch: it is what keeps project rename/delete and group CRUD out of reach of an unauthenticated caller. It builds a fresh `Headers` and deletes any `x-userId`/`x-role` the client sent before setting its own, because this branch never ran `authMiddleware` and the request's own headers are forwarded verbatim by `NextResponse.rewrite(url, {request: {headers}})`.
- `fake.middleware.ts` — `fakeMiddleware(req)`. The host router: a mock is addressed as `{projectId}.{DOMAIN}`, so this is what decides whether a request belongs to a project or to the app. `requestHost` reads the host from `x-forwarded-host` then `host`, lowercased, cut at the first comma a proxy may have chained on, and with a trailing dot and a default port dropped, since both still name the same host and would otherwise carry a mock host past the check. It is exported because the fake route compares a redirect's `Location` against that same host. The result is compared against the host in `DOMAIN`, with three outcomes: the apex itself or any host outside the wildcard returns `null` and the app answers, except for a path under `/api/fake/`, which is a 404 there because a rewrite never runs middleware again, so that path can only have been called directly; a label matching `PROJECT_PUBLIC_ID_REGEX` rewrites to `/api/fake/{label}`; anything else under the wildcard is an `ApiResponse.error` 404. That last branch is the point of the file: a subdomain never falls through to the app, so a label naming no project answers like a mock that does not exist rather than serving a second copy of the site on a host nobody should reach it on. `www` is not special-cased here and gets that same 404, because pointing a vanity host back at the app is a redirect on the domain itself and never needs to reach a function. Only the id goes onto the rewritten URL, because the route handler reads the mock path off the original `req.nextUrl.pathname`, which a rewrite leaves as the caller wrote it.

## Conventions

- Every middleware function returns either `null` (continue) or a `NextResponse` (short-circuit: a rewrite or an `ApiResponse.error`) — this is what lets `src/middleware.ts` chain them with simple `if (result) return result;` checks.
- A middleware never sets cookies/headers on the response itself; it only mutates the shared `ctx: MiddlewareContext` object or returns a short-circuit response, and the orchestrator (`src/middleware.ts`) applies `ctx` to the final response. `guest.middleware.ts` is the exception and returns its own rewrite carrying its own request headers, because it names a user without `ctx` and without `authMiddleware` ever running.
- A branch that skips `authMiddleware` owns its identity end to end, which includes deleting the `x-userId`/`x-role` a client may have put on the wire. `NextResponse.next`/`rewrite` forward the request's headers as they stand, so anything not deleted reaches `withUserId` as if middleware had set it.

Naming, ID, and other conventions that also apply outside this directory are in [src/server/AGENTS.md](../AGENTS.md) and the root [AGENTS.md](../../../AGENTS.md).
